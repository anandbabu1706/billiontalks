# BT-V0-020 — Cloudflare 406 / Media Mutation Stabilization

Date: 2026-10-09. Follows BT-V0-019.

## Production Symptom

Cloudflare Realtime returned HTTP 406 (`negotiation_in_progress`) during media mutations, including subscriber track creation and renegotiation. Subscriber media could remain stalled after the failed request.

## Inferred Mutation-Overlap Risk

The 406 response indicates that Cloudflare considered an earlier negotiation incomplete. Concurrent browser refreshes or recovery requests could send another mutation to the same subscriber session before the previous exchange had settled. This overlap is an inferred cause, not a confirmed Cloudflare-side root cause.

## Changes

- **Per-participant Durable Object media lock:** all POST SFU mutation routes serialize by the participant's session key through the meeting Durable Object. The lease prevents an abandoned holder from blocking forever; lock acquisition failure now returns 503 instead of proceeding without serialization.
- **Subscriber refresh coalescing:** subscriber mutations share an ordered browser queue, and overlapping refresh triggers coalesce so they do not race subscribe/renegotiate operations.
- **406 uncertain-outcome recovery:** a failed media mutation is not blindly retried against the same SFU session because Cloudflare may have applied an uncertain portion of the operation. Recovery clears local subscriber state and starts from a replacement session.
- **Subscriber session replacement:** recovery closes/replaces the browser subscriber PeerConnection, clears stale stream/track state, and re-subscribes active remote publications on the new session.
- **Cloudflare error capture:** upstream `errorCode` and `errorDescription` are bounded and retained with the HTTP status in errors and browser mutation diagnostics.
- **Duplicate publication deduplication:** identical publisher-session/track-name locators are collapsed before remote subscription requests.
- **Recovery-close tolerance:** an upstream close failure, including 406, is logged but does not prevent replacing the failed session.
- **`subscriberMutations` diagnostics:** `btMediaDiagnostics()` exposes a bounded mutation history with sequence, type, subscriber label, timestamps, signaling state, operation ID, HTTP status, upstream error details, and error text.

## Validation

- `npm test`: 202 tests passed across six files.
- `npm run typecheck`: passed.
- `npm run build`: Wrangler dry-run passed; nothing deployed.
- Tests cover mutation serialization, refresh/recovery ordering, 406 handling, session replacement, duplicate-track prevention, error diagnostics, duplicate publication deduplication, recovery-close tolerance, and lock-acquisition failure.

## Physical-Device Checks Still Required

- Reproduce or monitor the HTTP 406 on the affected physical device and confirm the captured Cloudflare error details.
- Confirm repeated subscriber refreshes and renegotiation no longer overlap on real browser/device timing.
- Confirm remote media resumes after a real 406 and replacement session without duplicate audio/video tracks.
- Validate recovery-close failure behavior and subscriber replacement across iOS Safari and Android Chrome.
- Confirm `subscriberMutations` contains enough diagnostic context from a production-device failure while avoiding exposure of SFU session identifiers.
