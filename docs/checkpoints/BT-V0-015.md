# BT-V0-015 — Final V0 Integration & Acceptance

Date: 2026-09-28.

## Delivered

- Shareable meeting links resolve to the existing meeting and open its prejoin flow.
- Host approval, participant/guest roles, and host-only controls work in the accepted browser flow.
- Host and participant coexist in the meeting with an established real media connection; screen sharing works through the meeting.
- Host-controlled recording captures the composed meeting stage and uploads media to private Cloudflare R2. Recording metadata becomes STOPPED only after multipart upload completion; capture, upload, and storage failures are recorded as FAILED.
- Recording object keys and multipart upload identifiers remain server-side and are excluded from public recording metadata.

## Recording Architecture and Limits

The host browser composites the visible meeting participant tiles into a canvas, mixes available audio, and captures the result with MediaRecorder. It uploads WebM data in ordered multipart requests to a private Cloudflare R2 bucket through authenticated Worker routes. The host browser does not receive the R2 object key or multipart upload identifier.

The host tab must remain open and active for the duration of recording. Capture is host-browser and tab-lifetime dependent; it is not a server-side Cloudflare Realtime SFU recording. A host capture or upload failure marks the recording FAILED rather than reporting a successful save.

Future direction: temporary BillionTalks storage, followed by export to user-owned storage, with optional retention-based deletion. No export, playback, or retention-deletion workflow is part of this V0 milestone.

## Acceptance Evidence

Manual acceptance was reported for the share link/prejoin flow, host approval and role restrictions, host/participant coexistence, live media connection, screen sharing, and recording capture to private storage. Automated regression tests cover UI flows, host authorization, R2 multipart retention/finalization, failure transitions, and metadata privacy.

The ADR's separate media-provider PoC gate is not fully evidenced by this milestone. Explicit two-way microphone/camera validation, reconnection validation, and sufficient media usage/cost observability remain to be recorded before ADR-001 can be Accepted. See [ADR-001](../decisions/ADR-001-media-architecture.md).
