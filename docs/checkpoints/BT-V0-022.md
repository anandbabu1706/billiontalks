# BT-V0-022 — Participant Publication Discovery

Date: 2026-10-09. Follows BT-V0-021.

## Production Diagnostic

The reported host diagnostics showed a connected publisher PeerConnection and ICE transport, a stable signaling state, successful HTTP 200 publish responses, and local `microphone` and `camera` tracks on mids `0` and `1`. In contrast, the host subscriber reported `remotePublicationCount = 0`, no subscription results or `ontrack` events, and a subscriber transport that remained in the `new` state. The host repeatedly received HTTP 200 from subscribe mutations while no remote publications were found.

These host-side values confirm that the failure occurs before remote track subscription and playback. They do not establish whether the guest's publish and ready requests succeeded or which server-side condition filtered the guest. Guest-side production diagnostics are still required to confirm the exact historical cause.

## Publication Lifecycle and Discovery

- A guest must be admitted and have a `JOINED` participant record before media publish is allowed.
- `/media/publish` creates/reuses the guest's Cloudflare publisher session and saves accepted track names and mids as pending publication state.
- `/media/publish/ready` promotes confirmed pending tracks into the participant's discoverable `publishedTracks`.
- SFU participant media state is stored in the meeting Durable Object, keyed by authenticated `userId`. Meeting snapshots only replace meeting metadata and do not erase that SFU record.
- Discovery now correlates the persisted state with meeting participant rows, excludes only the local participant by participant identity (with the legacy user-ID fallback), and includes eligible publications from any other joined participant. Display name and host/guest role are not used as self-identity.
- Subscribe responses and the read-only discovery response include participant-level diagnostic details: participant ID, user ID, display name, role, join state, publisher-session presence, track names/mids, inclusion decision, and exclusion reason. Orphaned or mismatched publisher state is identified without returning Cloudflare session IDs or bearer tokens.
- Successful publish and ready responses also include publisher state diagnostics, including publisher-session presence and published or pending track names/mids, without exposing session IDs or credentials.
- Added read-only `GET /api/meetings/{meetingId}/media/publications` so clients can refresh the desired publication set without mutating the SFU subscriber.
- The browser compares the discovered publication set and media connection with its last successfully subscribed set. It sends an SFU subscribe mutation only when that desired set changes; unchanged meeting refreshes still poll discovery but do not repeat an identical subscribe mutation.

## Validation

- `npm test`: 208 tests passed across six files.
- `npm run typecheck`: passed.
- `npm run build`: Wrangler dry-run passed; nothing deployed.
- Regression coverage verifies host and admitted guest camera/microphone publication and discovery in both directions, local-publication exclusion, identical display names, publication persistence across meeting snapshot refresh, and suppression of repeated unchanged empty subscribe mutations.
