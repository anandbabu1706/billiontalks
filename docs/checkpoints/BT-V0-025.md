# BT-V0-025 — Screen-Share Presentation UX

Follows BT-V0-024. Core bidirectional audio/video and screen-share transport are working in production; this checkpoint improves presentation display only.

## Presentation Behavior

- Presentation mode is driven by an active, live screen-video track, whether captured locally or received from a remote participant. Button state alone does not activate the layout.
- The active shared screen is promoted to a large primary presentation canvas. The share keeps its aspect ratio with `object-fit: contain`, avoiding stretching and cropping.
- Local and remote camera feeds remain available as secondary participant thumbnails in a camera strip.
- The **Focus / Full Screen** action enlarges the presentation area. It uses the browser Fullscreen API when available, with a fixed-position CSS focus fallback.
- When the active screen-share track ends, presentation mode and focus styling are cleared and the regular participant layout returns.
- Responsive styling prioritizes the presentation on mobile, places compact camera previews below it, and allows the strip to scroll horizontally without overflowing the page.

## Scope

No WebRTC/SFU transport, publisher/subscriber recovery, ICE, media-session lifecycle, or Cloudflare Realtime integration logic was changed. Screen-share capture, publishing, and stopping continue to use the existing transport lifecycle.

## Regression Coverage

Browser tests cover local and remote screen-share detection, presentation activation, normal-layout restoration after the share stops, camera preview availability, focus control behavior, and mobile presentation-first classes/layout.
