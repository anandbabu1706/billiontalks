# BT-V0-009 — Meeting Controls & Host Management Hardening

Base: `7910f10399e9f95ee928c185253d0d8bb2444e3c` (BT-V0-008).

## Delivered

- Host controls for OPEN, HOST_APPROVAL, and LOCKED access modes using the existing API.
- Persisted participant removal through `POST /api/meetings/:id/remove`; host/self/active-state checks, confirmation, and removal of only the selected guest.
- REMOVED lifecycle state prevents the same participant identity from rejoining or requesting admission, including after restart or a mode change. Voluntary leave remains rejoinable.
- Locked meetings reject approvals; ending a meeting resolves pending requests and closes joined participant states.
- Confirmation before ending for everyone; duplicate host actions are disabled while a request is pending, with recoverable failure messages.
- Three-second snapshot refresh for active rooms and waiting guests, including approval, rejection, removal, and meeting end. Stale responses from earlier host actions or departed sessions are ignored. Capture stops on removal/end/leave, including capture requests completing after departure.
- Participant/admission names and identifiers are escaped before insertion into generated markup.
- Durable Object transactional revision checks reject stale writes instead of overwriting newer state. Existing records without a revision start at zero; reads no longer write back snapshots.

## Validation

- `npm test`: 60 tests across five files, including rendered-page controls, local media mocks, service/API permissions, persistence restart, and concurrent/stale writes.
- `npm run typecheck`: passes.
- `npm run build`: passes (`wrangler deploy --dry-run`).
- Local `wrangler dev` smoke attempt was blocked by this execution environment's `uv_interface_addresses` system error before the Worker started. Real workerd runtime behavior was therefore not exercised here; Durable Object tests use the existing runtime shim and cloned storage fixtures.
- No live deployment or real multi-device media test was performed.

## Boundaries and remaining V0 work

Host-role checks still rely on client-supplied user IDs. This milestone does **not** establish authenticated identity or prevent an attacker from assuming another identity. Removal is identity-scoped, not a device/account ban. The next recommended milestone is **BT-V0-010 — Authentication & Session Security**, to establish server-verified identities and protect meeting mutations before public use.

Cloudflare Realtime SFU remains parked pending support case `02346261`. No SFU troubleshooting, credential rotation, app recreation, DNS changes, provider-code changes, or infrastructure configuration changes are included.
