# BT-V0-017 — Media Renegotiation and Screen-Share Stabilization

Date: 2026-10-07.

## Defect

Live external-device testing produced: `Failed to execute 'setRemoteDescription' on 'RTCPeerConnection': Failed to set remote offer sdp: The order of m-lines in subsequent offer doesn't match order from previous offer/answer.` Remote screen share was not rendered, participant video went blank, and microphones became intermittent after screen-share changes.

## Root Cause

- Stale subscriber tracks were closed on the Cloudflare session with `force: true` and no negotiation, so Cloudflare's m-line list diverged from the browser's. The next subscription offer no longer matched the previous negotiation (`/media/subscribe` handler).
- Publisher track close stopped transceivers and force-closed without an offer/answer (`closePublishedLocalTracks`).
- Remote screen tracks were merged into the camera `MediaStream`; a `<video>` plays only its first video track, so the screen was never shown.
- Publish snapshots were taken before the serialized queue ran, and failed negotiations left the connection in `have-local-offer`.

## Fix

- Publisher close stops only the screen transceivers, creates an offer, and sends it with the close; the Worker calls `tracks/close` with `force: false` and the offer and returns the answer. Microphone and camera transceivers and the publisher PeerConnection are preserved.
- Subscriber removals use a non-forced close; the returned offer is stored as a pending operation (`tracks: []`, `removed: [...]`) and finalized through the existing `/media/renegotiate` with its `operationId`.
- Publish snapshot is taken inside the queue; rollback runs after failed negotiations and before applying an offer on a non-stable connection.
- Remote screen tracks use a separate `screenStream` and `video.remote-screen-media` element; camera/mic streams are untouched.
- Forced close remains only for teardown and recovery. Reconnect/recovery behavior is unchanged.

## Validation

- `npm test`: 172 tests passed across six files (167 before).
- `npm run typecheck`: passed.
- `npm run build`: Wrangler dry-run passed; no deployment performed.
- New regressions: stable single publisher PeerConnection and m-line order across repeated share start/stop, overlapping toggles serialized, publisher recovery after a share lifecycle, remote camera/mic live through remote share start/stop/restart, and server-side non-forced subscriber/publisher close negotiation.

## Remaining Live Validation

Cloudflare's real behavior for non-forced `tracks/close` (offer for subscriber closes, answer for publisher closes) is unverified; tests use a simulated SFU. Validate on physical devices after deployment: camera + mic both ways, screen share start/stop/restart, remote screen rendering, mic stability, and reconnect after a share. Browser differences (Chrome, Safari, mobile) in recycling stopped m-lines, screen-share audio, and the camera tile being hidden during a remote share also need confirmation.

The Developer Tools panel is simulation-only and isolated from SFU state; it was not changed. ADR-001 status is unchanged.
